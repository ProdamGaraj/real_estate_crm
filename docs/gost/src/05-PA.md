# Структура программного обеспечения

Программное обеспечение системы состоит из общесистемного и специального ПО.

Общесистемное ПО — операционная система сервера, контейнерная платформа, СУБД, хранилище в оперативной памяти, обратный прокси, интерпретаторы и сторонние библиотеки. Оно распространяется его правообладателями и в составе системы не изменяется.

Специальное ПО разработано для системы и включает:

- серверную часть — веб-приложение на Python (фреймворк Django) с программным интерфейсом в стиле REST, командами управления и миграциями БД (каталог `backend`);
- клиентскую часть — одностраничное веб-приложение на TypeScript (библиотека React), исполняемое в браузере (каталог `frontend-new`);
- конфигурацию обратного прокси (каталог `nginx`) и описание развёртывания (`docker-compose.yml`, файлы `Dockerfile`);
- инструменты сборки документации (каталог `docs`).

Исходные тексты специального ПО хранятся в репозитории Git; опись приведена в документе «Текст программы».

# Функции частей программного обеспечения

## Обратный прокси и развёртывание

Конфигурация обратного прокси (`nginx/nginx.conf`, `nginx/conf.d/*.conf`) задаёт маршрутизацию запросов, зоны ограничения частоты запросов, заголовки безопасности, прямую отдачу общедоступных изображений и внутреннее расположение `/protected-media/` для отдачи защищённых файлов. Для работы по HTTPS используется шаблон `default-https.conf.template`. Файл `docker-compose.yml` описывает контейнеры, сети, тома и параметры среды.

# Операционная система

Серверная часть, СУБД, хранилище Redis и обратный прокси работают в контейнерах на базе Linux (Debian для образа серверной части `python:3.12-slim`, Alpine Linux для остальных образов). Сервер размещения — любая ОС семейства Linux с Docker Engine и Docker Compose (рекомендуется Ubuntu Server LTS или Debian). Для разработки допускаются Windows, macOS и Linux.

На рабочих местах пользователей требуется только веб-браузер: актуальные версии Google Chrome, Microsoft Edge, Mozilla Firefox, Safari, в том числе мобильные.

## Требования к ПО при развитии

При обновлении общесистемного ПО и библиотек необходимо:

1. обновлять версии в `requirements.txt` и `package.json` с фиксацией в `package-lock.json`;
2. выполнять автоматические тесты серверной части, проверку типов и сборку клиентской части;
3. проверять лицензию новой версии компонента;
4. при обновлении PostgreSQL на новую основную версию выполнять перенос данных через резервную копию по документу «Руководство системного программиста».
