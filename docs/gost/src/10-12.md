## Форма представления

Исходные тексты хранятся в репозитории системы контроля версий Git. Комментарии в исходных текстах выполнены на русском языке и объясняют назначение модулей и причины принятых решений.

Исходные тексты передаются заказчику:

- доступом к репозиторию Git (основной способ — с полной историей изменений);
- архивом ZIP, формируемым командой из подраздела 3.2.

Опись (раздел 2) составлена по файлам, находящимся под контролем версий, кроме сгенерированных файлов зависимостей (`package-lock.json`), изображений и документации. Контрольная сумма SHA-256 позволяет проверить, что содержимое файла совпадает с описанной редакцией.

# Получение исходных текстов и сборка программы

## Получение из репозитория

```
git clone <адрес репозитория> crm
cd crm
git checkout <коммит, указанный в разделе 2>
```

## Формирование архива

```
git archive --format=zip -o crm-sources.zip <коммит>
```

## Проверка соответствия описи

Контрольная сумма файла вычисляется командой `sha256sum <файл>` (Linux) или `Get-FileHash -Algorithm SHA256 <файл>` (Windows) и сравнивается с первыми 16 знаками, указанными в описи.

## Сборка

Сборка выполняется по документу «Руководство системного программиста» командой `docker compose up -d --build`. Для сборки клиентской части вне Docker: `cd frontend-new && npm ci && npm run build`. Серверная часть не требует компиляции; зависимости устанавливаются командой `pip install -r backend/requirements.txt`.
