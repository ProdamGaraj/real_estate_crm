# Общие сведения о программе

## Назначение программы

АС «CRM Недвижимость» автоматизирует продажи объектов недвижимости: учёт клиентов, заявок, встреч, каталога, сделок, платежей, задач и отчётность. Функции приведены в документе «Описание автоматизированных функций».

## Технические средства

Таблица: Требования к серверу
Ширины: 34, 66
| Параметр | Значение |
|---|---|
| Процессор | Не менее 2 ядер |
| Оперативная память | Не менее 4 ГБ |
| Диск | Не менее 40 ГБ плюс объём файлов и резервных копий; рекомендуется SSD |
| Сеть | Постоянный IP-адрес, доменное имя; открыты порты 80 и 443 |
| ОС | Linux (рекомендуется Ubuntu Server LTS или Debian) |

## Программные средства

На сервере должны быть установлены Docker Engine и Docker Compose (команда `docker compose`), а также Git для получения исходных текстов. Остальное ПО (PostgreSQL, Redis, nginx, Python, Node.js) поставляется в контейнерах. Состав ПО приведён в документе «Описание программного обеспечения».

## Сети

Сеть `frontend_network` связывает `nginx` и `frontend`. Сеть `backend_network` — внутренняя (без выхода в Интернет): в ней работают `nginx`, `backend`, `scheduler`, `db`, `redis`, `db-backup`. Сервисы `backend` и `scheduler` дополнительно подключены к сети `egress_network` — только для исходящих соединений: курсы валют ЦБ Узбекистана (`https://cbu.uz`) и SMTP-сервер. Порты БД и Redis наружу не публикуются.

Проверка выхода в Интернет: `docker compose exec backend python manage.py fetch_exchange_rates` — сообщение «Загружено курсов: N».

# Настройка программы

## Параметры среды

Параметры задаются в файле `.env` в корне репозитория (образец — `.env.example`). Файл передаётся в контейнеры `backend` и `scheduler` целиком; значения, перечисленные в разделе `environment` файла `docker-compose.yml`, имеют приоритет.

> Примечание – Docker Compose подставляет переменные в значения файла `.env`: знак «$» внутри значения начинает имя переменной, и часть значения пропадает. Записывайте «$» как «$$». Проверить итоговые значения можно командой `docker compose config`; предупреждение вида «The "w" variable is not set» означает, что в каком-то значении есть неэкранированный «$».

Ширины: 30, 70

|---|---|

## Первоначальная установка

1. Установите Docker Engine, Docker Compose и Git.
2. Получите исходные тексты: `git clone <адрес репозитория> crm && cd crm`.
3. Создайте файл параметров: `cp .env.example .env` и заполните обязательные параметры (подраздел 3.1).
4. Создайте каталоги файлов: `mkdir -p backend/media/{buildings,client_files,deals,layouts,projects,tasks,templates,avatars} backups`.
5. Для работы по HTTPS поместите сертификат и ключ в `nginx/ssl/fullchain.pem` и `nginx/ssl/privkey.pem` (подраздел 3.3).
6. Запустите комплекс: `docker compose up -d --build`. Миграции БД применятся автоматически.
7. Создайте разрешения и типовые роли: `docker compose exec backend python manage.py init_permissions`. Типовые роли создаются, пока в системе нет ни одной роли.
8. Создайте первого системного администратора: `docker compose exec backend python manage.py createsuperuser`, затем `docker compose exec backend python manage.py setup_admin_permissions --username <логин>`. Учётной записи суперпользователя автоматически присваивается признак «Системный администратор».
9. Выполните проверку по разделу 4.
10. Дальнейшую настройку (компании, пользователи, справочники, каталог) выполняет администратор в интерфейсе системы по ролевой инструкции администратора.

## Настройка HTTPS

Обратный прокси включает HTTPS автоматически при наличии файлов `nginx/ssl/fullchain.pem` и `nginx/ssl/privkey.pem`. Для сертификата Let's Encrypt:

```
docker compose stop nginx
certbot certonly --standalone -d crm.example.uz
cp /etc/letsencrypt/live/crm.example.uz/fullchain.pem nginx/ssl/
cp /etc/letsencrypt/live/crm.example.uz/privkey.pem nginx/ssl/
docker compose up -d nginx
```

После включения HTTPS установите в `.env` `REFRESH_COOKIE_SECURE=True` (значение по умолчанию) и при необходимости `CSRF_TRUSTED_ORIGINS=https://crm.example.uz`, затем выполните `docker compose up -d backend scheduler`. Сертификат Let's Encrypt действует 90 дней: настройте продление (например, заданием cron с остановкой nginx на время продления) и перезапуск nginx после копирования новых файлов.

## Настройка почты

Укажите в `.env` параметры SMTP-сервера (`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USE_TLS` или `EMAIL_USE_SSL`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`) и адрес системы `FRONTEND_URL` (из него строится ссылка в письме), затем перезапустите `backend`. Проверка — запрос восстановления пароля для своей учётной записи.

## Обновление системы

1. Создайте резервную копию БД и файлов (подраздел 5.1).
2. Получите новую редакцию: `git pull`.
3. Пересоберите и перезапустите: `docker compose up -d --build`. Миграции применятся при запуске `backend`; ход виден в `docker compose logs -f backend`.
4. Если в редакции добавлены ресурсы или изменён состав типовых ролей, выполните `docker compose exec backend python manage.py init_permissions --sync-roles`. Команда обновляет состав только типовых (системных) ролей; ролям, заведённым вручную, разрешения на новые ресурсы выдаются в «Настройки» → «Роли». Отсутствующие типовые роли в системе со своими ролями не создаются — удалённые администратором дубли при обновлении не появятся снова; создать их можно ключом `--with-roles`.
5. Выполните проверку по разделу 4.

> Примечание – При переходе на редакцию с мультивалютностью дополнительно:
>
> 1) загрузите историю курсов с даты первой сделки, чтобы отчёты за прошлые периоды пересчитывались: `python manage.py fetch_exchange_rates --since ГГГГ-ММ-ДД`;
> 2) если прайс компании вёлся в долларах, а сделки создавались с пометкой «UZS»: укажите проектам валюту прайса (в карточке проекта или `relabel_currency --company <id> --projects USD`) и пересчитайте старые сделки в валюту сделок командой `convert_deals_currency --company <id> --assume-from USD` — сначала без `--apply`, затем с ним. Если суммы сделок должны остаться в долларах, вместо пересчёта исправьте пометку: `relabel_currency --company <id> --deals USD`;
> 3) задайте валюту сделок и поддерживаемые валюты компании («Настройки» → «Валюты») и валюту прайса проектов;
> 4) выдайте ролям, ведущим курсы (администратор компании, финансист), разрешения на ресурс «Курсы валют».

> Примечание – Перед применением миграции `realty.0013` (уникальность номера объекта в пределах дома) выполните `python manage.py find_duplicate_units` и устраните повторы: при их наличии миграция прерывается с сообщением о повторяющихся номерах.

# Проверка программы

## Проверка работоспособности комплекса

1. `docker compose ps` — все контейнеры в состоянии `running`; для `backend`, `db`, `redis`, `frontend`, `nginx` — `healthy`.
2. `curl -f https://<адрес>/api/health/` — ответ с кодом 200.
3. `curl -f http://<адрес>/nginx-health` — ответ с кодом 200.
4. Вход в систему под учётной записью администратора, открытие дашборда.
5. `docker compose logs --tail 50 scheduler` — регламентные задания выполняются без ошибок.

## Проверка после установки или обновления

Выполните в контейнере `backend`:

```
python manage.py check
python manage.py showmigrations | grep "\[ \]"
python manage.py test apps permissions
```

Первая команда не должна сообщать о проблемах, вторая — выводить неприменённых миграций, третья — завершаться сообщением `OK`. Тесты создают временную БД и не затрагивают рабочие данные; для их выполнения пользователю БД необходимо право создавать базы данных.

# Дополнительные возможности

## Резервное копирование и восстановление

### Резервное копирование

Контейнер `db-backup` создаёт копию БД каждое воскресенье в 03:00 и хранит четыре еженедельные и три ежемесячные копии в каталоге `backups`. Рекомендуется:

- выполнять копирование ежедневно — изменить параметр `SCHEDULE` сервиса `db-backup`, например на `@daily`, и `BACKUP_KEEP_DAYS` на 7;
- копировать каталоги `backend/media` и `backups`, а также файл `.env` на другой сервер или в облачное хранилище средствами площадки (например, `rsync` по расписанию);
- не реже раза в квартал проверять восстановление на испытательном стенде.

Внеочередная копия БД:

```
docker compose exec db pg_dump -U $DB_USER -d $DB_NAME -Fc > backup_$(date +%F).dump
```

Копия файлов:

```
tar czf media_$(date +%F).tar.gz backend/media
```

### Восстановление

```
docker compose stop backend scheduler
docker compose exec db dropdb -U $DB_USER $DB_NAME
docker compose exec db createdb -U $DB_USER $DB_NAME
docker compose exec -T db pg_restore -U $DB_USER -d $DB_NAME < backup.dump
tar xzf media_YYYY-MM-DD.tar.gz
docker compose up -d backend scheduler
```

Для копий контейнера `db-backup` (формат SQL, сжатие gzip) используйте `gunzip -c <файл>.sql.gz | docker compose exec -T db psql -U $DB_USER -d $DB_NAME` вместо `pg_restore`. Восстанавливайте вместе с БД файлы того же момента и прежний `SECRET_KEY`.

## Журналы

Журналы серверной части: `docker compose exec backend ls /app/logs` — `django.log` (работа приложения), `security.log` (события безопасности, отказы в доступе), `app.log` (прикладные события). Потоковые журналы: `docker compose logs -f backend` (включая журнал запросов gunicorn), `docker compose logs -f nginx`.

| `fetch_exchange_rates [--date ГГГГ-ММ-ДД] [--since ГГГГ-ММ-ДД]` | Загрузка курсов ЦБ: действующих, на дату или за период по сегодня |
| `convert_deals_currency --company <id> --assume-from <валюта> [--rate <курс>] [--date ГГГГ-ММ-ДД] [--apply]` | Пересчёт старых сделок компании (созданных до указания валюты прайса) и их платежей в валюту сделок по одному курсу, по умолчанию — сегодняшнему. Исходные суммы и курс сохраняются в сделке и платежах, в журнал сделки пишется запись. Сделки с суммами больше `--max-amount` (5 000 000) и с платежами, введёнными в другой валюте, пропускаются; повторный запуск ничего не пересчитывает дважды. Без `--apply` — пробный запуск |
| `relabel_currency --company <id> [--deals <валюта>] [--projects <валюта>] [--apply]` | Исправление пометки валюты у сделок и их платежей и у прайса проектов компании без пересчёта сумм. Сделки, суммы которых получены пересчётом (при брони или командой `convert_deals_currency`), и сделки с платежами, введёнными в другой валюте, не трогаются. Без `--apply` — пробный запуск с перечнем изменений |
| `reset_passwords`, `create_test_users` | Только для испытательных сред |
