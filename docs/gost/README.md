# Проектная документация АС «CRM Недвижимость»

Комплект документов по ГОСТ 34 и ЕСПД. Документы собираются из исходных текстов в Markdown, поэтому правятся вместе с системой: изменили поведение — поправили текст в `src/` и пересобрали.

Указатель всей документации (ролевые инструкции + этот комплект) — `docs/index.html`.

Оформление — по ГОСТ 2.105-2019 (текстовые документы) и ГОСТ 19.106-78 (программные документы): лист А4 без рамки, поля 30/15/20/20 мм, Times New Roman 12 пт, полуторный интервал, абзацный отступ 1,25 см; нумерация разделов «1», «1.1», «1.1.1»; таблицы «Таблица N – Название» над таблицей, рисунки «Рисунок N – Название» под рисунком; приложения «Приложение А (обязательное/справочное)» с нумерацией «А.1»; перечисления «–», «а)», «1)»; номер страницы и обозначение документа — в верхнем колонтитуле; титульный лист (для ЕСПД — также лист утверждения); лист регистрации изменений в конце.

## Перед утверждением

1. Заполните реквизиты в `meta.json`: полное наименование заказчика, организацию-разработчика, должности и ФИО утверждающих и согласующих.
2. Замените заглушки кодов `ХХХХ`, `ХХХХХХ`, `ХХХХХХХХ` в `meta.json` присвоенными кодами организации и классификационной характеристики системы. Обозначения собираются по образцу ГОСТ 34.201-2020 (документы П2, П3 и т.д.) и ГОСТ 19.103-77 (документы ЕСПД, страна `UZ`); перед утверждением сверьте структуру обозначений с правилами, принятыми у заказчика.
3. Согласуйте с заказчиком значения показателей назначения в ТЗ (подраздел 4.1.3): число пользователей, время отклика, объёмы данных. Это предлагаемые значения, нагрузочные испытания по ним не проводились.
4. Подтвердите применимость стандартов. Стандарты ГОСТ Р — национальные стандарты Российской Федерации; в комплекте они использованы как методическая основа там, где нет межгосударственного стандарта (содержание документов, стадии, виды испытаний). Актуальность редакций проверьте по реестру стандартов на дату утверждения.
5. Зафиксируйте изменения в репозитории и пересоберите комплект: опись «Текста программы» составляется по коммиту.

## Сборка

Требуется Python 3 с пакетами `python-docx` и `Pillow`.

```
python docs/gost/tools/build.py               # все документы → docs/gost/out/*.docx
python docs/gost/tools/build.py 03-P3         # один документ
powershell -ExecutionPolicy Bypass -File docs/gost/tools/finalize.ps1   # Windows + Word: оглавление, число листов, PDF
```

Оглавление и число листов — поля Word. Без `finalize.ps1` они рассчитываются при открытии файла в Word клавишей F9 (выделить всё — F9).

### Данные, которые берутся из кода

- `data/models.json`, `data/routes.json` — снимок моделей и маршрутов API. Обновлять после изменения моделей или маршрутов (из каталога `backend`, в окружении проекта):

  ```
  python ../docs/gost/tools/snapshot.py
  ```

  Из снимка строятся каталог таблиц БД и классификаторы (П5, приложения А и Б) и перечень маршрутов (документ 33, приложение А).
- `data/fig-*.png` — схемы, рисуются кодом: `python docs/gost/tools/diagrams.py`.
- Опись исходных текстов (документ 12) строится при сборке по файлам под контролем версий Git.

## Формат исходных текстов

Файл начинается с шапки:

```
---
title: Описание автоматизированных функций
kind: gost34            # gost34 — документ ГОСТ 34; espd — документ ЕСПД (с листом утверждения)
code: П3                # код вида документа
file: 03_П3_Описание_автоматизированных_функций
standard: ГОСТ Р 59795-2021
annotation: Текст аннотации || второй абзац      # для документов ЕСПД
---
```

Разметка тела:

| Запись | Результат |
|---|---|
| `# Заголовок`, `## …`, `### …` | Раздел, подраздел, пункт с автоматической нумерацией; раздел начинается с новой страницы |
| `# !Перечень терминов и сокращений` | Структурный элемент без номера, по центру прописными |
| `# @А \| справочное \| Название` | Приложение; заголовки `##` внутри нумеруются «А.1» |
| `- текст` / `1. текст` | Перечисление «–» / «а)»; вложенный уровень (отступ 2 пробела) — «1)» |
| `Таблица: Название` + `Ширины: 20, 80` + таблица `\| … \|` | Таблица с номером, шириной колонок в долях и повторяемой шапкой |
| `Рисунок: Название \| data/файл.png \| 160` | Рисунок шириной 160 мм с подписью |
| `> Примечание – …` | Примечание |
| ` ``` … ``` ` | Листинг моноширинным шрифтом |
| `**жирный**`, `*курсив*`, `` `код` ``, `<br>` | Выделения и перенос строки в ячейке |
| `::: snippet terms` | Вставка общего фрагмента `src/_snippets/terms.md` |
| `::: catalog`, `::: tables`, `::: classifiers` | Каталог таблиц БД, перечень таблиц, классификаторы (из снимка) |
| `::: routes`, `::: manifest`, `::: documents` | Маршруты API, опись исходных текстов, перечень документов комплекта |
| `\pagebreak` | Разрыв страницы |

Номера таблиц и рисунков в ссылках из текста («в таблице 4») проставляются вручную — после правок проверьте, что ссылки указывают на нужные таблицы.
