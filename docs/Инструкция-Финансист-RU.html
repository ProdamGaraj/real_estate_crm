Как вести платежи в CRM

Руководство для финансового отдела: построение графика платежей по сделке, ежедневная отметка поступлений, контроль просрочки, возвраты при расторжении и сверка данных с бухгалтерией.

01Ваша зона и её границы

Главное правило системы: платёж существует только внутри сделки.

Отдельный платёж создать нельзя. В системе нет кнопки «создать платёж» — платежи появляются только при сохранении графика платежей по конкретной сделке. Раздел Финансы показывает уже созданные платежи и позволяет менять их состояние, но не заводить новые.

Из этого следует порядок работы: если денег ждут по сделке, у которой нет графика, — сначала заводится график на шаге 3 сделки, и только потом появляются платежи, которые можно отмечать.

02Вход и раздел «Финансы»

Ваш основной экран и что на нём есть.

  1. Войдите: Имя пользователя и Пароль от администратора, кнопка Войти. Логин — не email.

  2. Откройте раздел Финансы.

В разделе две вкладки:

  • Список платежей — все платежи в вашей области видимости с фильтрами.
  • Сводная таблица — итоги по группам, виджеты и выгрузка в Excel.

Фильтры списка

ФильтрКогда использовать
КлиентРазбор по конкретному плательщику
ID СделкиВсе платежи одной сделки
Дата к оплате (от / до)План поступлений на период
Факт оплаты (от / до)Что реально пришло за период — основа сверки

Различайте две даты. Дата к оплате — плановый срок из графика. Дата фактической оплаты — когда деньги поступили. Для отчёта о поступлениях фильтруйте по второй, для планирования — по первой.

Клик по строке открывает карточку платежа: сумма и валюта, тип платежа, метод (наличные или безналичные), счёт получателя, обе даты, ссылки на клиента и сделку, а также кнопки действий.

03График платежей

Шаг 3 сделки. Здесь стоимость по договору разбивается на транши.

  1. Откройте Сделки, найдите нужную и перейдите на шаг График платежей.

  2. Нажмите Добавить платеж — по строке на каждый транш.

  3. В строке заполните Сумма, Дата к оплате, Тип платежа и Счет получателя.

  4. Контролируйте счётчики сверху: Сумма по договору, Распределено, Остаток.

  5. Когда Остаток равен нулю, нажмите Сохранить график. Появится подтверждение «График платежей успешно сохранен!».

Сумма платежей обязана точно совпадать со стоимостью по договору. При расхождении система возвращает ошибку с обеими суммами: «Сумма платежей (…) не совпадает со стоимостью по договору (…)» — и график не сохраняется. Копейки тоже считаются: округляйте так, чтобы разница уходила в последний транш.

После первого сохранения графика сделка автоматически переходит из статуса Бронь в В работе, а объект — из Бронь в Сделка в работе. В логах сделки появляется запись с суммой графика.

Поля платежа
ПолеЧто учесть
СуммаЧисло без пробелов; сумма всех строк = стоимость по договору
Дата к оплатеПлановый срок. По нему считается просрочка
Тип платежаИз справочника: первоначальный взнос, рассрочка, доплата и т.д.
СчетСчёт получателя, на который ожидается поступление
ВалютаПо умолчанию — валюта сделки. Можно выбрать другую валюту, разрешённую в компании: при сохранении строка пересчитается в валюту сделки по курсу на сегодня, а введённая сумма и курс останутся видны в графике
Вид платежаНаличные или безналичные

Весь график хранится в валюте сделки. Сумма платежа в списке, отметки оплаты, просрочка и отчёты считаются в ней. Доллар делится только до цента, поэтому графиком в долларах точную сумму договора в сумах обычно не набрать: разница в несколько сумов от округления допускается и добавляется к последнему пересчитанному платежу.

При правке графика строки показываются в валюте сделки; у строк, которые не меняли, сохраняются сведения о том, как их вводили. Оплаченные платежи не пересчитываются.

Если в выпадающих списках Тип платежа или Счет пусто, справочники ещё не заполнены — график сохранить не получится. Это настраивает администратор, см. главу 10. В списках видны только записи вашей компании и общие для всех, заведённые системным администратором.

04Правка графика

Условия сделки меняются — график можно пересобрать, не потеряв проведённые платежи.

Проведённые платежи защищены. При сохранении изменённого графика строки с отметкой об оплате сохраняются как есть: статус Оплачен и дата фактической оплаты остаются на месте. Пересобираются только непроведённые транши.

Как править график

  1. Откройте сделку, шаг График платежей, нажмите Редактировать график.

  2. Строки уже проведённых платежей заблокированы — вместо кнопки удаления в них показан статус (Оплачен, К возврату, Возвращен). Сумму и срок в них изменить нельзя.

  3. Правьте непроведённые строки: суммы, сроки, типы платежей. Ненужные удаляйте, недостающие добавляйте кнопкой Добавить платеж.

  4. Следите, чтобы Остаток снова стал нулевым.

  5. Нажмите Сохранить график.

Оплаченный платёж нельзя убрать из графика. Если попытаться сохранить график без него, система откажет и перечислит такие платежи: «Нельзя удалить из графика платежи, по которым уже прошли деньги». Чтобы всё-таки убрать транш, сначала отмените по нему оплату — и только если деньги действительно не поступали.

Что происходит с суммой. Правило равенства действует по-прежнему: сумма всех строк, включая заблокированные, должна совпадать со стоимостью по договору. Стоимость договора менеджер может изменить, пока по сделке нет проведённых платежей; после первой оплаты она замораживается. Если стоимость пересмотрели, разницу распределяйте по непроведённым траншам — уже полученные деньги переписать нельзя, и это правильно.

Правка недоступна, если сделка отменена или расторгнута — система вернёт ошибку «Сделка отменена или расторгнута — изменить график платежей нельзя».

05Отметка оплат

Ежедневная операция: подтвердить, что деньги пришли.

Отметить оплату можно из двух мест — результат одинаковый:

Из карточки платежа

Финансы → клик по строке → кнопка Отметить как оплаченный. Удобно при работе по банковской выписке.

Из графика сделки

Карточка сделки → шаг График платежей → кнопка Оплачен в строке. Удобно, когда клиент вносит несколько траншей сразу.

Датой оплаты проставляется сегодняшнее число. Задним числом отметить платёж кнопкой нельзя. Если поступление было раньше, отметьте платёж и сообщите об этом в комментарии к сделке либо согласуйте порядок с бухгалтерией — расхождение в дате отразится в отчёте о поступлениях за период.

Исправление ошибки

  1. Откройте платёж, отмеченный по ошибке.

  2. Нажмите Отменить оплату (в графике сделки — кнопка Отменить).

  3. Платёж вернётся в статус К оплате — или сразу в Просрочен, если плановая дата уже прошла.

Обе операции — и отметка, и её отмена — записываются в логи платежа с указанием даты и автора.

По отменённой или расторгнутой сделке отметить оплату нельзя. Кнопки Отметить как оплаченный и Отменить оплату в этом случае недоступны, и такой запрос отклонит сам сервер — остаётся только возврат, см. главу 07. Дату оплаты будущим числом система тоже не примет.

06Просроченные платежи

Статус «Просрочен» система проставляет сама, по расписанию на сервере.

Как это работает. Платежи со статусом К оплате, у которых Дата к оплате уже прошла, автоматически переводятся в Просрочен. Пересчёт выполняет служебная задача на сервере — она же снимает истёкшие брони и закрывает забытые встречи. Дополнительно статусы освежаются при открытии списка платежей, сводной таблицы и дашборда, но не чаще раза в несколько минут. Поэтому цифра просрочки одинакова во всех трёх местах и не зависит от того, кто и когда заходил в систему.

Новый платёж с уже прошедшим сроком получает статус Просрочен сразу при сохранении графика.

Ежедневная работа с просрочкой

  1. Откройте Финансы → Список платежей.

  2. Задайте Дата к оплате (до) — вчерашнюю дату.

  3. Перейдите на Сводная таблица и посмотрите виджет Просроченные платежи — там общая сумма.

  4. Сгруппируйте По менеджеру, чтобы передать списки на обзвон, или По проекту — для отчёта руководителю.

  5. Выгрузите в Excel и отправьте ответственным.

Сумма просрочки также выводится на Дашборд в блоке Просроченные платежи — её видят руководитель и директор, поэтому цифра должна быть актуальной.

07Возвраты

Что делать с деньгами клиента после расторжения сделки.

РасторжениеОформляет отдел оформления
→
К возвратуСистема ставит статус сама
→
Фактический возвратДеньги уходят клиенту
→
ВозвращенВы закрываете статус

При расторжении сделки все платежи со статусом Оплачен автоматически переводятся в К возврату. С этого момента они — ваша зона ответственности.

  1. Найдите такие платежи: Финансы → Сводная таблица → группировка По статусу, либо отфильтруйте список по нужной сделке.

  2. Проведите фактический возврат денег клиенту по принятой в компании процедуре.

  3. Откройте платёж и нажмите Отметить как возвращенный (в графике сделки — кнопка Вернуть).

  4. Статус изменится на Возвращен, в логах появится запись «Платеж отмечен как возвращенный».

Статус К возврату — это открытое обязательство перед клиентом. Пока по платежу не нажата кнопка возврата, компания числится должником. Проверяйте этот статус отдельным пунктом каждую неделю: такие платежи не попадают ни в просрочку, ни в поступления, и потому легко теряются из виду.

Кнопка возврата доступна только для платежей в статусе К возврату. Для платежа в любом другом статусе система вернёт ошибку «Платеж не может быть отмечен как возвращенный».

08Сводные таблицы и Excel

Инструмент для отчётности и передачи данных за пределы CRM.

  1. Откройте Финансы → Сводная таблица.

  2. Задайте период. Для отчёта о поступлениях используйте Факт оплаты (от / до), для плана — Дата к оплате (от / до).

  3. Выберите Группировать по.

  4. Нажмите Выгрузить в Excel.

ГруппировкаКакой вопрос закрывает
СтатусуСколько ждём, сколько получили, сколько просрочено и сколько должны вернуть
ПроектуКакой ЖК приносит деньги, а какой отстаёт по собираемости
МенеджеруЧья дебиторка растёт — материал для руководителя отдела продаж. Ответственным за платежи считается менеджер сделки: он проставляется автоматически при создании графика

Виджеты над таблицей показывают Просроченные платежи и Оплаченные платежи за выбранный период — отдельной парой на каждую валюту. Суммы в разных валютах не складываются в одно число, поэтому и в таблице есть колонка Валюта: одна строка группы на каждую валюту.

Если валют несколько, над ними выводится общий итог в валюте сделок компании: просроченные платежи пересчитываются по курсу на дату к оплате, оплаченные — на дату оплаты. Если для какой-то валюты нет курса, её суммы в общий итог не входят, и система об этом предупреждает.

Выгрузка содержит ровно то, что вы видите на экране. Она ограничена вашей областью видимости и наложенными фильтрами. Если в файле не хватает данных, проверьте сначала фильтры, а затем — свою область доступа.

09Сверка с бухгалтерией

CRM — не бухгалтерская программа. Она отражает договорные обязательства, а не проводки.

Регулярная сверка защищает от расхождений между тем, что видит отдел продаж, и тем, что стоит в учёте.

  1. Выгрузите из CRM платежи за период с фильтром по Факт оплаты (от / до).

  2. Сопоставьте с банковской выпиской по каждому Счет получателя.

  3. Разберите расхождения по типам из таблицы ниже.

  4. Исправьте в CRM то, что относится к CRM, и зафиксируйте остальное для бухгалтерии.

РасхождениеВероятная причинаЧто делать
Деньги в банке есть, в CRM платёж «К оплате»Забыли отметить оплатуОтметить как оплаченный
В CRM «Оплачен», в банке поступления нетОшибочная отметкаОтменить оплату
Суммы совпадают, даты нетОтметка сделана позже фактического поступленияЗафиксировать в акте сверки: в CRM дата ставится днём отметки
Транш в CRM есть, в выписке его нет вовсеГрафик правили: непроведённые транши пересобраныСверить с текущим графиком сделки, см. главу 04
Поступление есть, сделки нетПлатёж по сделке вне CRM или предоплата до брониПровести бронь и график, затем отметить

Сверяйтесь по счетам получателей. Разбивка по Счет сразу показывает, к какой выписке относится строка. Если счетов в компании несколько, а в CRM заведён один, попросите администратора завести остальные — иначе сверка каждый раз будет ручной.

10Справочники и счета

Два справочника, без которых не сохраняется ни один график.

СправочникЧто содержитГде используется
Типы платежейПервоначальный взнос, рассрочка, доплата и другие принятые в компании видыПоле Тип платежа в графике
Счета получателейНазвание счёта и банковские реквизиты компанииПоле Счет в графике

Эти справочники находятся в разделе Настройки›Финансы. Доступ администратор выдаёт двумя правами: Просмотр на ресурс Настройки — он открывает сам раздел, и права на Типы платежей и Счета получателей — они добавляют вкладку. В боковом меню появится пункт Настройки, и в нём будет только вкладка Финансы — остальные (роли, пользователи, API-ключи) вам не покажут.

Добавить тип платежа или счёт

  1. Откройте Настройки›Финансы.

  2. Для типа платежа нажмите Новый тип и введите Название типа платежа — ровно так, как оно должно отображаться в графике.

  3. Для счёта нажмите Новый счёт, введите Название счёта и полные реквизиты — они попадают в документы.

  4. Сохраните. Новое значение сразу доступно менеджерам в графике платежей.

Использованный справочник не удаляется. Счёт получателя, по которому уже есть платежи, система удалить не даст и скажет, сколько записей на него ссылается. Заведите новый счёт, а прежний оставьте для истории — на старых платежах он должен сохраниться.

Счета привязаны к компании: заведённый счёт виден только в своей компании. Если в системе несколько юрлиц, счёт заводится в каждом отдельно. Если пункта Настройки в меню нет — прав пока не выдали, запросите у администратора доступ к ресурсам Типы платежей и Счета получателей.

Проверьте справочники до старта продаж по новому проекту. Если типов платежей или счетов нет, менеджер упрётся в это на третьем шаге сделки — и придёт к вам в самый неудобный момент.

Валюты и курсы

Вкладка Настройки›Валюты открывается при правах на ресурс Курсы валют.

БлокЧто в нём
Валюта сделокОдна на компанию. В ней ведутся новые сделки и графики, к ней приводятся дашборд и отчёты. Смена действует только для новых броней
Поддерживаемые валютыВ каких ещё валютах менеджер может вводить строки графика. Валюта сделок входит всегда
Курсы на сегодняКурс каждой поддерживаемой валюты — сколько сумов за единицу, дата курса и источник
Ручной курсКурс на дату, который в вашей компании действует вместо курса ЦБ
История курсовКурсы ЦБ и ручные курсы компании; ручной курс можно удалить

  1. Курсы ЦБ Узбекистана загружаются автоматически каждый час. Если нужно обновить их сразу, нажмите Обновить курсы ЦБ.

  2. Если ЦБ недоступен или компания считает по своему курсу, заполните Ручной курс: валюта, дата, курс в сумах за единицу — и нажмите Добавить.

Для пересчёта на дату берётся последний курс не позже этой даты. Ручной курс на ту же дату важнее курса ЦБ и действует только в вашей компании. После удаления ручного курса на его дату снова действует курс ЦБ. Курсы ЦБ не удаляются.

11Поступления в отчётах

Как ваши отметки превращаются в управленческий отчёт.

В разделе Отчеты формируется отчёт план-факт по проектам и по сотрудникам. Он состоит из трёх блоков, и один из них питается напрямую вашими данными:

Блок отчётаОткуда берутся цифры
Кол-во, шт.Количество закрытых сделок
КонтрактацияСуммы подписанных договоров
ПоступленияПлатежи, отмеченные как оплаченные

Денежные блоки отчёта приведены к валюте сделок компании (она указана в заголовке колонки): контрактация — по курсу на дату договора, поступления — по курсу на дату оплаты. План загружается в той же валюте.

Прямое следствие. Неотмеченный платёж — это недополученная выручка в отчёте руководителя и заниженный % факт по поступлениям. Отметки, сделанные с опозданием в несколько дней, смещают деньги в следующий отчётный период.

Разрыв между Контрактация и Поступления — это дебиторская задолженность компании. Именно этот разрыв руководитель обсуждает на планёрке, и объяснять его чаще всего приходится финансовому отделу. Держите просрочку и возвраты в актуальном состоянии, чтобы разговор шёл о реальных деньгах, а не о неаккуратных данных.

12Логи платежей

Каждое действие с платежом записывается автоматически.

ДействиеЧто попадает в лог
Отметка оплаты«Платеж отмечен как оплаченный. Дата оплаты: …» с автором и временем
Отмена оплаты«Оплата отменена. Предыдущая дата: …»
Возврат«Платеж отмечен как возвращенный.»
Создание графикаВ логах сделки: сумма графика и смена статуса сделки на «В работе»
Обновление графикаВ логах сделки: «График платежей обновлен. Новая общая сумма: …»

Как это выручает. Если состав графика не совпадает с ожидаемым, откройте Логи сделки: запись об обновлении графика покажет, кто и когда его менял и сколько платежей было добавлено, изменено и удалено. Это сразу даёт и объяснение, и адресата вопроса.

Логи доступны только для чтения. Удалять записи может лишь сотрудник с отдельным правом на удаление логов.

13Ритм работы

Готовый распорядок. Можно распечатать и держать под рукой.

Каждый день

Отметить вчерашние поступления по выписке. Просмотреть новые просроченные платежи и передать списки на обзвон.

Каждую неделю

Проверить платежи в статусе К возврату и закрыть проведённые возвраты. Сводка по просрочке в разрезе менеджеров и проектов для руководителя.

Каждый месяц

Сверка с бухгалтерией по каждому счёту получателя. Проверка блока Поступления в отчёте план-факт. Ревизия справочников перед стартом новых проектов.

Чек-лист перед закрытием месяца
  1. Все поступления по выписке отмечены в CRM.
  2. Нет ошибочных отметок: суммы в CRM и в банке сходятся по каждому счёту.
  3. Возвраты по расторгнутым сделкам проведены и закрыты статусом Возвращен.
  4. Сумма просрочки на дашборде соответствует реальности.
  5. Блок Поступления в отчёте план-факт совпадает с вашей выгрузкой за период.

14Частые вопросы

Как создать платёж, не привязанный к сделке
Никак — в системе такой возможности нет. Платежи создаются только при сохранении графика платежей по сделке. Если поступление относится к сделке без графика, сначала заведите график.
График не сохраняется
Сумма всех платежей не равна Стоимость по договору. В тексте ошибки система показывает обе суммы. Добейтесь нулевого Остаток.
Над графиком сообщение «Нет курса …», график не сохраняется
Курс валюты, в которой введена строка, не загружен. Нажмите Обновить курсы ЦБ или введите ручной курс в Настройки›Валюты.
Сумма платежа в графике не круглая
Строку вводили в другой валюте, и при сохранении она пересчитана в валюту сделки. Под суммой показано, сколько и по какому курсу вводили. Копеечная разница от округления добавляется к последнему пересчитанному платежу.
В списке «Тип платежа» или «Счет» пусто
Справочники не заполнены. Заведите значения в Настройки›Финансы. Если пункта «Настройки» в меню нет — запросите у администратора право Просмотр на ресурс Настройки вместе с правами на типы платежей и счета получателей: одного без другого недостаточно.
Сохранится ли отметка об оплате при правке графика
Да. Проведённые платежи не пересоздаются: статус и дата фактической оплаты остаются. В форме правки такие строки заблокированы и помечены статусом.
Не даёт убрать транш из графика
По этому платежу уже прошли деньги — система перечислит такие строки в тексте ошибки. Сначала отмените по нему оплату, и только если поступления действительно не было.
Нужно отметить оплату вчерашним числом
Кнопка всегда ставит сегодняшнюю дату, выбрать другую нельзя. Отметьте платёж и зафиксируйте фактическую дату в акте сверки с бухгалтерией.
Кнопка «Отметить как оплаченный» неактивна
Сделка расторгнута — по ней отметка оплаты запрещена. Либо платёж уже в статусе Оплачен, и вместо этого доступна отмена.
Платёж не переходит в статус «Возвращен»
Кнопка возврата работает только для статуса К возврату. Он появляется автоматически после расторжения сделки с оплаченными платежами.
Статус «Просрочен» не проставился, хотя срок прошёл
Пересчёт идёт по расписанию на сервере и при открытии разделов «Финансы» и «Дашборд». Если статус не изменился — проверьте, что срок действительно прошёл и платёж не отмечен оплаченным. Если не меняется и на следующий день, скажите администратору: возможно, остановлена служебная задача (сервис scheduler).
Не вижу платежи по сделкам другого отдела
Ваша область видимости уже нужной. Для работы финансиста требуется область Компания — запросите её у администратора.
Сумма в отчёте план-факт меньше, чем в моей выгрузке
Сверьте периоды: отчёт строится по выбранному году и периоду, а выгрузка — по вашим фильтрам. Проверьте также, что фильтровали по Факт оплаты, а не по Дата к оплате.
Клиент заплатил больше, чем стоит в графике
Система требует точного равенства суммы графика и стоимости по договору, поэтому «лишний» платёж в график не добавить. Решение согласуется с руководителем: либо пересматривается стоимость по договору на шаге «Условия сделки», либо переплата оформляется вне CRM.
Нужен ещё один счёт получателя
Заведите его сами в Настройки›Финансы кнопкой Новый счёт. Счёт создаётся в вашей компании; для другого юрлица его нужно завести отдельно.
